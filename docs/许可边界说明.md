# 客户端与 sing-box 的许可边界

核对日期：2026-10-22。对象：代理小助手 0.1.20 客户端源码，以及其调用的 sing-box 1.14.3。

## 当前源码核对结果

| 核对项 | 当前实现 |
| --- | --- |
| 客户端语言和构建 | `src/` 为 C#；`构建.ps1` 直接使用 .NET Framework 编译器，只引用 `System*.dll` 系统程序集 |
| 内核载入方式 | `src/CoreRunner.cs` 以独立进程启动 `core/sing-box.exe`，没有静态或动态链接 sing-box/libbox |
| 输入 | 使用公开 CLI `check -c stdin` / `run -c stdin`，经标准输入传递 JSON 配置 |
| 数据结构 | `src/CoreConfig.cs` 构造内核公开配置字段；未见共享内存或交换内核内部对象结构 |
| 输出 | 标准输出/错误只用于识别固定的内核启动状态；代理流量通过网络协议转发 |
| 原生调用 | 当前 `DllImport` 目标为 Windows 系统 DLL，未见加载第三方内核库 |
| 本仓库内容 | 包含客户端源码、编译资源和文档；不包含 sing-box 源码或二进制 |

0.1.20 增加连接后的健康交叉检查及对应回归测试；它沿用上述独立内核调用方式，新增文件未引入内核链接或第三方代码包。

这些事实支持把当前发布范围作为独立客户端材料单独许可；本次静态检查未发现必须对当前源码目录整体应用 GPL 的直接链接或内核代码混入证据。该结论不等于两份许可证本身可以互相兼容地合并代码，也不构成“任何打包或修改后都绝对没有冲突”的保证。

## 官方条款如何适用

[GPLv3 第 5 节](https://www.gnu.org/licenses/gpl-3.0.html#section5)允许由独立作品构成的聚合包分别保持各自许可，但不得用聚合包条款缩减其中 GPL 作品的权利。[GNU FAQ 的聚合说明](https://www.gnu.org/licenses/gpl-faq.en.html#MereAggregation)要求同时考虑通信方式与语义；独立进程、管道或命令行只是判断因素，不能单独决定是否属于独立作品。基于当前公开 CLI 和配置通信方式，本项目保留独立程序边界，并在 README 中明确排除对内核施加非商业限制。

sing-box v1.14.3 的 [原始 LICENSE](https://github.com/SagerNet/sing-box/blob/v1.14.3/LICENSE)采用 GPL-3.0-or-later，并有名称与关联声明。原文副本位于 `LICENSES/sing-box-LICENSE.txt`；GPL 全文位于 `LICENSES/GPL-3.0.txt`。复制这些许可文本不改变它们的适用范围。

客户端使用 [PolyForm Noncommercial 1.0.0 原文](https://polyformproject.org/licenses/noncommercial/1.0.0)，原文存于根目录 `LICENSE`。`NOTICE` 的 `Required Notice:` 行用于保留作者版权通知。未取得单独书面许可的商业用途不在其一般授权范围内；许可证明示允许的特定组织用途及法定权利仍然适用，不通过 README 暗中删除或收窄这些条款。

## 不能据此做的事

- 将 sing-box 或其他 GPL 派生代码复制、翻译改编、链接进客户端后，仅靠拆分目录或另加 `LICENSE` 声称其不受 GPL 约束。
- 将带内核的完整便携包标成“所有内容未经作者授权均不得商用”，从而限制用户依 GPL 使用内核。
- 把两个 EXE、相同压缩包或公开配置接口本身当作永久有效的法律豁免。
